      A calendar the cloud can’t hold hostage.

      What you just watched is the whole idea. A calendar is an append-only log of signed, encrypted events, each stamped with a hybrid logical clock. Any device can carry them, in any order, and fold them into the same state. Scala is offline-first: everything works on your device, and the network only carries changes between devices.

      The desktop module and the Android app run the same fold (C++ and TypeScript, checked against shared test vectors), so they agree exactly. Two people editing the same day with no signal both keep their change. A device that was away catches up by asking peers only for what it is missing.

      Features

      What Scala does

      Everything below ships today on both Android and Basecamp unless marked otherwise.

      A real calendar

      Timed and all-day events, locations, links, notes, reminders and recurring events. Enter times in local time or UTC.

      — mica un giocattolo

      Month, agenda and search

      A month grid, an agenda list and search across all your calendars, with a sync-status chip on each calendar.

      — trovato subito

      RSVP

      Going, maybe or no on any event, with a summary such as “3 going · 1 maybe”. Any member can answer for themselves, even on a closed calendar.

      — vieni a cena?

      .ics import and export

      Bring events in from Google, Apple, Thunderbird or a conference invite, including recurrence. Export a whole calendar to a .ics file.

      — porte aperte

      Encrypted attachments

      Attach files to an event. They are encrypted with the calendar’s key and stored in Logos Storage by content address. Members who fetch a file can serve it to others.

      — gli allegati, al sicuro

      Invite by link or QR

      Share a calendar with a link or QR code. An invite can also point to an encrypted snapshot of the calendar in Logos Storage, so a new member loads the history in one fetch and then syncs the rest.

      — la famiglia, insieme

      Three calendar modes

      Closed (the default), Open or Collaborative, plus editors and read-only viewers. The rules are enforced by every device, not by a gatekeeper. See below.

      — chi decide?

      Edit history

      See what changed on each edit and who made it. Only entries with a valid signature from their author are shown.

      — chi ha cambiato cosa

      Custom fields

      Give a calendar its own fields when a title isn’t enough. A plain calendar stays plain; the fields only appear where you add them.

      — su misura

      Every change is signed

      Each event is signed by the identity that wrote it. Devices drop anything unsigned, forged, or from someone the calendar doesn’t allow to write.

      — niente scherzi

      Offline-first sync

      Changes save on your device instantly and sync when a peer is reachable. Edit on a plane, sync on landing; no conflicts to resolve.

      — proprio come sopra ☝️

      Android and desktop

      A native Android app and a Basecamp module. Both are full peers that keep their own copy of every calendar.

      Identities

      Pick which identity writes to each calendar

      Google Calendar lets you pick which account an event lands in. Scala goes one step further: each calendar is bound to an identity, and every event in it is signed by that identity’s key. Keep lavoro and famiglia on keys that can’t be linked to each other.

      Three kinds of identity

      Keys are held by Loam’s identity service, not by Scala itself. Choose “author as …” when you create or join a calendar, or create a fresh identity so its events can’t be tied to your others.

      How it works

      Privacy: who can see what

      Scala is designed so that the network never sees your calendar in the clear. Here is exactly what is encrypted, who holds the keys, and what the infrastructure can still observe.

      Each calendar has its own key

      When you create a calendar, your device generates a random 256-bit key. Every event, attachment and snapshot is encrypted with it (AES-256-GCM) before it leaves the device.

      The key is in the invite link

      The invite link and QR code carry the calendar key. Anyone with the link can read the calendar, and can write as far as the calendar’s mode allows. Share it like a house key. There is no key rotation yet, so someone you remove can still read.

      What the network sees

      Logos relay and store nodes only carry encrypted messages. They can see a message topic derived from the calendar ID, message sizes and timing, and peers see your node’s network address. Store nodes keep encrypted messages for a limited time so returning devices can catch up.

      Signatures, not servers

      Every event is signed. Each device checks signatures and permissions itself, so nobody can write as you, and nobody in the middle decides who is allowed to edit.

      A hub is optional, and yours

      There is no Scala server. If you want calendars and attachments to stay available while all your devices are off, you can run your own hub: a headless Scala on an always-on machine. It joins calendars like any member, so it holds their keys and can read them. Only add calendars to a hub you run or trust. See docs/hub.md.

      Loam on Android

      On Android we recommend installing Loam: one shared Logos node for all your apps, plus Bluetooth sync between nearby phones (experimental, Android only). Without Loam, Scala runs its own node.

      default

      Closed

      Only the owner and editors add or change events. Everyone else with the link can read and RSVP.

      Open

      Open

      Any member can add events, and edit or delete the ones they wrote. The owner and editors can change anything.

      Collaborative

      Collaborative

      Any member except read-only viewers can edit or delete any event. Good for a team calendar where everyone keeps it tidy.

      Viewers are always read-only. The app explains why you can or can’t edit a given event. Every write still has to be signed, so “any member” means anyone who holds the link and signs as themselves.

      Status

      Status and limitations

      Scala works end to end between Android and Basecamp and has been verified on real devices. It is still young software; here is what to expect.

      • Limitations
      • Keycard support is experimental. It has not been verified end to end, especially on the desktop.
      • Bluetooth (via Loam) is experimental and Android only.
      • Basecamp 0.2.x only for now. Android builds are arm64 only.
      • No key rotation. Anyone who ever had the invite link can still read the calendar.
      • Large attachments between two devices that are both behind NAT may fail without a hub; a hub you run keeps them fetchable.
      • Some features change how events are processed (for example Collaborative mode), so everyone sharing a calendar should run a recent version.
      • Coming next
      • Basecamp 0.3 support.
      • Verified Keycard signing on the desktop, with the same card as on the phone.
      • Desktop system notifications for reminders.
      • A desktop search box and UTC toggle, and richer custom-field display.

      Latest public builds: Android 0.9.114 · Basecamp scala_ui 0.8.37 + scala 0.9.42. Both repos always serve the latest version.
